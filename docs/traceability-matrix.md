# Requirements Traceability Matrix (RTM)

**IEM Lost & Found Management System** | **Team P8, Section B** | **PCC-CS504**

This document provides end-to-end traceability between each Functional Requirement (FR-01 to FR-20) from the Software Requirements Specification (SRS) and the implementing code across the Angular client and Node.js/Express/MongoDB server.

| FR ID | Priority | Requirement Description | Implementing Files & Code Locations | Status |
|:---:|:---:|---|---|:---:|
| **FR-01** | High | The system shall allow students, faculty, and staff to register using their name, institutional email, user type, and password. | • Server Model: `server/src/models.js` (`User.userType` enum: `student`, `faculty`, `staff`, `admin`)<br>• Server Route: `server/src/routes.js` (`POST /api/auth/register`)<br>• Client Form: `client/src/app/pages/login.component.ts`<br>• Client Auth: `client/src/app/core/auth.ts` (`register()`) | **Done** |
| **FR-02** | High | The system shall authenticate registered users using their email and password before allowing access to protected functions. | • Server Route: `server/src/routes.js` (`POST /api/auth/login`)<br>• Server Middleware: `server/src/middleware.js` (`auth` JWT verification)<br>• Client Auth: `client/src/app/core/auth.ts` (`login()`, `authInterceptor`, `authGuard`)<br>• Client Routes: `client/src/app/app.routes.ts` (`canActivate: [authGuard]`) | **Done** |
| **FR-03** | Medium | The system shall allow users to search reports using item name or keywords and display matching results. | • Server Route: `server/src/routes.js` (`GET /api/items?q=...`)<br>• Client API: `client/src/app/core/api.ts` (`items()` with query params)<br>• Client UI: `client/src/app/pages/home.component.ts` (real-time search bar) | **Done** |
| **FR-04** | High | The system shall allow users to filter reports by category, location, date, and lost/found type. | • Server Route: `server/src/routes.js` (`GET /api/items` with `type`, `category`, `location`, `fromDate`, `toDate`)<br>• Client API: `client/src/app/core/api.ts` (`items()` filters)<br>• Client UI: `client/src/app/pages/home.component.ts` (category select, location input, date range filters) | **Done** |
| **FR-05** | High | The system shall allow users to select an item category from predefined categories such as electronics, documents, bags, books, accessories, keys, and others. | • Server Model: `server/src/models.js` (`CATEGORIES` enum)<br>• Server Route: `server/src/routes.js` (`GET /api/categories`)<br>• Client Form: `client/src/app/pages/report.component.ts`<br>• Client Edit Form: `client/src/app/pages/item-details.component.ts` | **Done** |
| **FR-06** | High | The system shall display the details and current status of an individual lost or found report to authorized users. | • Server Route: `server/src/routes.js` (`GET /api/items/:id`)<br>• Client UI: `client/src/app/pages/item-details.component.ts`<br>• Client Routing: `client/src/app/app.routes.ts` (`/item/:id`) | **Done** |
| **FR-07** | Medium | The system shall allow the original reporter to edit an active report before it is returned or closed. | • Server Route: `server/src/routes.js` (`PUT /api/items/:id`)<br>• Client API: `client/src/app/core/api.ts` (`updateItem()`)<br>• Client UI: `client/src/app/pages/item-details.component.ts` (Edit Report form and toggle button) | **Done** |
| **FR-08** | High | The system shall allow the original reporter to cancel an active report, after which it shall be removed from active search results. | • Server Route: `server/src/routes.js` (`POST /api/items/:id/cancel`)<br>• Client API: `client/src/app/core/api.ts` (`cancel()`)<br>• Client UI: `client/src/app/pages/item-details.component.ts` ("Cancel report" button) | **Done** |
| **FR-09** | Medium | The system shall allow authenticated users to log out and terminate their active session. | • Client Auth: `client/src/app/core/auth.ts` (`logout()` purges local state and session)<br>• Client UI: `client/src/app/pages/profile.component.ts` ("Log out" button) | **Done** |
| **FR-10** | Medium | The system shall compare lost and found reports using category, description, location, date/time, and identifying features to generate possible matches. | • Server Engine: `server/src/matching.js` (`score()`, `aiCompare()`, `runMatching()`)<br>• Server Route: `server/src/routes.js` (background matching run on item report and update) | **Done** |
| **FR-11** | High | The system shall allow users to report a lost item by entering item name, category, description, location, date, and approximate time. | • Server Route: `server/src/routes.js` (`POST /api/items` with `type: 'lost'`)<br>• Client UI: `client/src/app/pages/report.component.ts` | **Done** |
| **FR-12** | High | The system shall reject an incorrect verification answer and lock the claim for 30 minutes after 3 consecutive failed attempts. | • Server Model: `server/src/models.js` (`ClaimLock` schema tracking `failedAttempts` and `until`)<br>• Server Routes: `server/src/routes.js` (`lockOf`, `recordFailedAttempt`, `resetFailedAttempts`, HTTP 423/403 responses)<br>• Client UI: `client/src/app/pages/item-details.component.ts` (attempt feedback and lockout countdown messaging) | **Done** |
| **FR-13** | High | The administrator dashboard shall display total reports, active reports, matched items, pending claims, returned items this month, and average time-to-match. | • Server Route: `server/src/routes.js` (`GET /api/admin/stats` aggregating all 6 metrics)<br>• Client API: `client/src/app/core/api.ts` (`stats()`)<br>• Client UI: `client/src/app/pages/profile.component.ts` (Admin Dashboard Overview grid widget) | **Done** |
| **FR-14** | High | The system shall maintain item statuses as Reported → Matched → Pending Verification → Returned, with Cancelled and Rejected as additional states. | • Server Model: `server/src/models.js` (`ITEM_STATUSES`, `statusHistory` subdocument array)<br>• Server Routes: `server/src/routes.js` (lifecycle transitions and history logging)<br>• Server Migration: `server/src/migrate.js`<br>• Client UI: `client/src/app/pages/item-details.component.ts` (status badge and interactive Status History timeline) | **Done** |
| **FR-15** | High | The system shall generate a match notification when the matching score reaches at least 70%. | • Server Engine: `server/src/matching.js` (`THRESHOLD()` check and `notify()` for both reporters)<br>• Client UI: `client/src/app/pages/my-items.component.ts` (Notifications list with unread markers) | **Done** |
| **FR-16** | High | The administrator shall be able to review reports and claims, approve/reject claims, manage inappropriate reports, and update item status. | • Server Routes: `server/src/routes.js` (`GET /api/claims`, `POST /api/claims/:id/approve`, `POST /api/claims/:id/reject`, `DELETE /api/items/:id`, `POST /api/items/:id/moderate`)<br>• Client API: `client/src/app/core/api.ts` (`review()`, `moderateItem()`, `deleteItem()`)<br>• Client UI: `client/src/app/pages/item-details.component.ts` (Admin Moderation tools), `client/src/app/pages/profile.component.ts` (Pending Claims review) | **Done** |
| **FR-17** | High | The system shall allow a user to submit a claim for a found item by identifying the relevant lost-item report. | • Server Routes: `server/src/routes.js` (`POST /api/matches/:id/claim`, `POST /api/items/:id/claim`)<br>• Client UI: `client/src/app/pages/item-details.component.ts` (`startMatchClaim()`, manual match linking) | **Done** |
| **FR-18** | Medium | The system shall assign each possible match a score from 0% to 100% and display higher-scoring matches first. | • Server Engine: `server/src/matching.js` (normalized integer scores 0–100)<br>• Server Routes: `server/src/routes.js` (`.sort('-score')`)<br>• Client UI: `client/src/app/pages/item-details.component.ts` (sorted list with percentage badges) | **Done** |
| **FR-19** | High | The system shall require the claimant to correctly answer an item-specific verification question before the claim can be approved. | • Server Routes: `server/src/routes.js` (`GET /api/items/:id/question`, bcrypt verification on claim submission)<br>• Client UI: `client/src/app/pages/item-details.component.ts` (claim modal with question prompt and answer input) | **Done** |
| **FR-20** | High | The system shall allow users to report a found item using item name, category, description, location, date, and approximate time. | • Server Route: `server/src/routes.js` (`POST /api/items` with `type: 'found'`, `verificationQuestion`, `verificationAnswerHash`)<br>• Client UI: `client/src/app/pages/report.component.ts` | **Done** |
